1. Integration Architecture & Base URLs

MAIL INDIA provides a low-latency, asynchronous transactional email pipeline built on top of high-reputation SMTP nodes.

Production Base URL
https://mailindia.in/v1

Live production cluster with guaranteed Mumbai data residency.

Local / Sandbox Base URL
http://localhost:3000/v1

Local development server with instant test sending.

Lifecycle Workflow:
  1. Sign Call: Client backend attaches API Key in header Authorization: Bearer mi_live_...
  2. Pre-flight Checks: System validates recipient syntax, queries real-time suppression list, and reserves 1 credit idempotently.
  3. Immediate Acceptance: Returns 202 Accepted with a 64-character message_id in <15ms.
  4. Async Delivery: Background worker relays via verified Gmail/Custom SMTP and commits credit deduction.

2. Authentication & Headers

All API requests must be authenticated using your project API Key passed as a Bearer token in the Authorization HTTP header.

Header Type Requirement Description
Authorization string Required Bearer token format: Bearer mi_live_xxxxxxxxxxxxxxxxxxxxxxxx
Content-Type string Required Must be set to application/json for all POST/PUT requests
Idempotency-Key string Recommended Unique client UUID or order key (e.g. order-8921) to prevent duplicate sends and duplicate credit debits on network retry.
🛡️
Security Warning: Never expose your API key in client-side HTML, frontend JavaScript bundles, or public Git repositories. Always trigger email dispatches from your backend server or cloud functions.

package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"net/http"
	"os"
	"time"
)

type EmailRequest struct {
	To             string `json:"to"`
	Subject        string `json:"subject"`
	Text           string `json:"text"`
	HTML           string `json:"html,omitempty"`
	Consent        bool   `json:"consent"`
	IdempotencyKey string `json:"idempotency_key,omitempty"`
}

func main() {
	reqBody, _ := json.Marshal(EmailRequest{
		To:             "recipient@example.com",
		Subject:        "Alert: Server Spike",
		Text:           "High CPU utilization detected on node 4.",
		Consent:        true,
		IdempotencyKey: fmt.Sprintf("go-%d", time.Now().Unix()),
	})

	req, _ := http.NewRequest("POST", "http://localhost:3000/v1/emails/send", bytes.NewBuffer(reqBody))
	req.Header.Set("Authorization", "Bearer "+os.Getenv("MAIL_INDIA_API_KEY"))
	req.Header.Set("Content-Type", "application/json")

	client := &http.Client{Timeout: 10 * time.Second}
	resp, err := client.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Println("Status Code:", resp.StatusCode)
}

            + "\"to\":\"client@example.com\","

        RequestBody body = RequestBody.create(json, MediaType.get("application/json; charset=utf-8"));

            .url("http://localhost:3000/v1/emails/send")
            .addHeader("Authorization", "Bearer " + System.getenv("MAIL_INDIA_API_KEY"))
            .post(body)
            .build();

        try (Response response = client.newCall(request).execute()) {
            System.out.println("HTTP Status: " + response.code());
            System.out.println("Response: " + response.body().string());
        }
    }
}

4. Send Transactional Email

POST /v1/emails/send

Enqueues a transactional email for asynchronous dispatch, validates consent, checks suppression, and verifies balance.

Request Body Schema (JSON)

Field Type Requirement Description
to string Required Valid destination email address. Validated against RFC 5322 and checked against the suppression database.
subject string Required Subject line of the email (1 - 250 characters). Line breaks and CRLF injection characters are rejected.
text string Required* Plain-text fallback body. Recommended for maximum inbox deliverability. (Required if html is omitted).
html string Optional Rich HTML body. Supports inline CSS and responsive transactional email styling.
consent boolean Required Must be set to true. Confirms lawful customer consent under transactional transmission guidelines.
idempotency_key string Optional Unique client-supplied idempotency key (1 - 128 characters). Prevents duplicate email dispatches or duplicate charges on connection retries.

Lifecycle Status Definitions:

queued

Request validated and queued in the asynchronous dispatch buffer.

processing

Worker has claimed the job and is negotiating SMTP handshake.

accepted

Upstream SMTP provider confirmed receipt; credit finalized.

failed

Pre-send validation failed; reserved credit immediately refunded.

Signature Verification (Node.js)

const crypto = require('crypto');

function verifyWebhook(payloadRawBuffer, signatureHeader, webhookSecret) {
  const expected = crypto
    .createHmac('sha256', webhookSecret)
    .update(payloadRawBuffer)
    .digest('hex');
  return crypto.timingSafeEqual(Buffer.from(signatureHeader), Buffer.from(expected));
}

7. Error Codes Reference & Troubleshooting

Every error returned by MAIL INDIA includes a machine-readable error string and a human-readable message.

Error Code HTTP Status Meaning Resolution / Action
INVALID_API_KEY 401 API key is missing, corrupted, or has been revoked. Generate a new live key from API Keys Management.
INSUFFICIENT_CREDITS 402 Wallet balance is depleted (0 available credits). Top up wallet credits using UPI / NetBanking at Buy Credits.
RECIPIENT_SUPPRESSED 403 The target recipient previously bounced permanently or filed an abuse complaint. Do not send to this address. If verified valid, remove from the Suppression List.
IDEMPOTENCY_CONFLICT 409 An existing job with this key was already created with different payload attributes. Use a new unique UUID for distinct emails, or pass identical parameters for retries.
RATE_LIMIT_EXCEEDED 429 Your workspace exceeded the allocated API rate limit (default 120 req/min). Queue dispatches with exponential backoff or contact support to request an enterprise burst increase.
SENDER_UNAVAILABLE 500 Assigned SMTP sender credentials failed health check or are paused. Verify sender credentials in settings. Ensure App Password is valid without spaces.

8. Production Best Practices & Deliverability

Guidelines to achieve 99.8%+ inbox placement and zero bounce rates.

🛡️ Use Idempotency Keys

Always supply an Idempotency-Key header (such as your database order ID or user signup UUID). This ensures network retries never double-charge or duplicate recipient emails.

📄 Supply Both Text & HTML

Always include a clean text version alongside your html. Spam filters penalize HTML-only emails and reward clean multi-part alternatives.

⚡ Handle Async Acceptance

Store the returned message_id in your database. Poll /v1/emails/:id or listen to webhooks to track delivery confirmation.

🚫 Respect Suppression Rules

Never bypass RECIPIENT_SUPPRESSED responses. Repeatedly sending to hard-bounced addresses damages domain reputation.
